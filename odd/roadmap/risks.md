## 6. Risks

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Scope D2 is broad (11 strategies incl. V-Carve, Inlay, Moulding) | Plan inflation, half-finished strategies | Milestones ordered so each is shippable; V-Carve and Moulding isolated at M7/M8; UI never blocks a strategy |
| Free-profile nesting (NFP) is NP-hard and quality-sensitive | M9 slips | Ship rectangle nesting first (covers cabinetry parts), free profiles second |
| Offsetting with arcs is where CAM kernels break | Wrong geometry silently | Arc-preserving offset library + property tests with randomized polygons; tolerance surfaced as a job setting |
| egui limits dense CAD UI | Rework of UI shell | Shell behind an adapter; `cxx-qt` swap documented, domain untouched |
| PDF/EPS vector import fidelity | Users blame the app for their file | Import report that lists dropped/approximated entities instead of failing silently |
| Simulation performance on large jobs | UI stalls | **M5:** the documented cell cap (4,000,000 cells, 32 MB of surface heights), a decimation stride that keeps the mesh's lattice within 200 sampled lines, and a single-threaded, untiled removal loop (D-M5-8). Parallel or tiled removal lands when a measured simulation of a default sheet at the default resolution exceeds one second |
| No machine-gate for `.pp` compatibility | Users bring malformed post-processors | Strict parser with located diagnostics and a dry-run "validate post-processor" command |
| **The simulation's field and the program used different origins** (M6 L17) — **closed in M7, T0, commits `d8cb895` + `4d6849e`.** `cam_sim::grid::grid_for` built the field at `(0, 0)` from `job.width/height` while programs are emitted in machine coordinates, so at any origin corner other than bottom-left the report and the preview disagreed with the document about *where* the cut is, for every strategy since M5 | Before: a correct program on an 80 x 30 mm band in a 200 x 100 mm sheet reported `gouge 14376.000 mm³ over 2396 cells` and `uncut 14400.000 mm³ over 2400 cells` at `top_left`, against `gouge 0.000` / `uncut 24.000 mm³ over 4 cells` at bottom-left. After: **the bottom-left numbers at all three corners** (`removed 14376.000`, `gouge 0.000`, `uncut 24.000 over 4`). The emitted G-code was never affected; the report and the 3D preview were | Closed as the roadmap's own recorded next step, in one slice: one `cam_model::Frame` honoured at every boundary — the field's grid and cell mapping, the program's coordinates, and the **handedness of every arc and helix** — with a **test per origin corner** and 13 tests in all. D-M7-8 records the crossing point the implementation found: the field, the target and the preview stay in the document frame and the program is read into it once, because M5 places a tab by arc length from the contour's start, so reflecting the target would move every tab at `top_left` |
