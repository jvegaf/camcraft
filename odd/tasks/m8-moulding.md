## Specs

Requirements as stated by the owner (user strings verbatim, in the user's language where applicable):

- **S1** — Roadmap M8 row (verbatim, `odd/roadmap.md:146`): "| **M8** | Moulding / swept profile | Rail + profile sweep with stepover | Needs the 3D-adjacent math from M7's distance field |". This is the only M8 specification in the plan; there is no §4.x subsection and no acceptance criteria.
- **S2** — What the README promises (verbatim, `README.md:20`): "Moulding (a swept profile) is next (M8)." And (verbatim, `README.md:255`): "M8 is moulding: a rail and a profile swept along it with a stepover, the first strategy whose answer depends on a cross-section rather than a single depth. It was scheduled after V-carve because it needs the distance field M7 built."
- **S3** — The owner's scope decision for M8 (verbatim option label chosen 2026-11-04): "Sección Z barrida por el rail". The chosen option's description (verbatim as presented): "El rail va en XY, el perfil dice (distancia lateral, profundidad Z), stepover son pasadas laterales solapadas." Recorded interpretation, not a new requirement: rail = XY path, profile = cross-section (lateral offset, Z depth), stepover = overlapped lateral passes. Any deviation reopens S3 and its tasks.
- **S4** — Rule 1 of the architecture, in force since M0 (verbatim, `odd/roadmap.md` §3): "**`cam-cli` is the contract.** Any behaviour that cannot be produced headless through the CLI is not considered testable, and therefore not done."
- **S5** — Rule 2 of the architecture, in force since M0 (verbatim, `odd/roadmap.md` §3): "**Determinism is a feature.** Identical input must produce byte-identical G-code. No `HashMap` iteration may reach an output path; ordering is explicit (`BTreeMap`, sorted IDs, stable sorts)."
- **S6** — Verification rule 5 (verbatim, `odd/roadmap.md` §5): "**Simulation as oracle** — for each strategy, a test asserts the simulated removed volume matches the analytic expectation within tolerance; a too-shallow pocket fails the test, not a screenshot." Applies to M8 with a cross-section footprint instead of a single depth.
- **S7** — Assumption (not a user order, carried from D-M4-8 / M7 S15): M8 is authored through `cam-cli toolpath`; no toolpath form in the window. Precedent string (`crates/cam-ui/src/strategy.rs:104`): "This shell drafts a profile and a pocket; the rest are authored with `cam-cli toolpath`". If the owner orders a shell form, S7 is rewritten and a task is added; it is not silently absorbed.
