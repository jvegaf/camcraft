Campilot — the staged workflow

Today the shell is one flat column: ui.label, DragValue, separator, again — 25 labels, 21 drag values, 14 buttons, one CentralPanel. The reference app's answer is not more UI: it is named stages with gates, so at any moment the screen shows one job and one question. The rail is stage-scoped — that is how 65 icons never appear at once.

04 The teaching voice, inside the tool

Three rules for every string in the UI

1. Consequence before mechanics. Say what the operator will get or lose before saying which field to touch.

“Outside drops the part free. Inside cuts holes and windows. On cuts along the line — the centre of the tool rides the vector.”

2. Second person, no jargon. “Select the vectors, then press Generate” — never “invoke the emitter with a validated stream”.

3. Every refusal names a number. Not “invalid toolpath”: “Tool 3.2 mm cannot enter the 2.5 mm gap at node 61.”

This is the same discipline the reference app uses in its help map: one short sentence of what, one of how, and the warning that saves a sheet of MDF.

V-carve F1

Cuts along the centre of closed vectors: the tip follows each point's own distance to the boundary, so the depth narrows where the shape narrows and the corners stay sharp.

Select closed vectors and a tool of type V-bit. The depth is not typed — it comes from the included angle.

  • Max depth — the stop where the cone reaches full width. Never deeper than the stock.
  • Flat tip — a tool with a flat leaves a floor; leave 0 for a true point.
  • Stepover — how much of the untouched ridge is re-cut on the next pass.

05 What the stages force us to build the honest backlog this concept implies

Shell

· TopBottomPanel for the app bar, a second for the stage bar, a third for the status bar — the flat CentralPanel today cannot express any of this.

· SidePanel left, fixed 52 px, stage-scoped content.

· SidePanel right, 288 px, collapsible with hover-reveal; inspector tabs + persistent layer list.

· A theme singleton publishing the token set in design/camui-shell/04-tokens.html; egui Visuals stays untouched — we own the frame.

Not in this round

· No new geometry, no new toolpath maths, no change to the document format. The stages must be able to describe what already exists in c2d/document@2.

· No rewriting the CLI: cam-cli stays the contract, the shell reads the same results.

· Rotary relief stays out until its own milestone; the stage bar shows the stages the document can already prove.
